## Learned Workspace Facts

- This repo is the Void, Cloudflare, and TanStack Start rewrite of the Next.js app at `/Users/kalongchan/programmer/tuen-mun-pathfinder`. `tuenmunpathfinder.com` and `www.tuenmunpathfinder.com` are custom domains on this Worker. The zone is on Cloudflare; do not point the site back at Vercel. Leave mail records (MX, SPF, DKIM, DMARC) and CAA records in place.
- The database is Cloudflare D1 (SQLite via Void). Do not set Postgres in `void.config.ts`, and do not add Neon, a Neon `DATABASE_URL`, or Hyperdrive.
- Void allows only one root `.env` file. Do not create `.env.example` or `.env.local`. `env.ts` is the schema; `.env` is local-only and is not uploaded on deploy.
- Nocoly is the source for meetings (集會), 活動資料 (notices, album links, 精選相簿, and Mux videos), 相片分類, 首頁圖片, 其他頁面設定, 幼鋒會榮譽證, and 幼鋒會手冊. Those rows are copied into D1. Notice PDFs stay on Nocoly and are served through `/api/notices/:id/file/:slot` (`pathfinder` and `adventurer`). Photo files stay on Google Cloud. Past-video playback uses Mux playback IDs stored in D1; Mux API tokens are not used by the Worker. The site does not use web or app push.
- 幼鋒會榮譽證 is managed in Nocoly. Each row stores 要求 and 答案 as both Markdown and HTML, one badge, an optional Word file, and Chinese and English single-page PDFs. The two handbooks are a single row on 幼鋒會手冊. `/adventurer-honors` reads published HTML from D1. Badge images live in Cloudflare R2 and are served from `/api/adventurer-honors/:id/badge`; a missing badge is fetched from Nocoly and stored in R2. Word files, single-page PDFs, and handbooks stay on Nocoly. The website serves Word and single-page PDFs only to admins; the iOS app reads them at `/api/app/honors/:id/file/:slot`. Each sync uploads at most 24 changed badges and continues the rest later. Certificate files are not stored in the repo. Honor card padding is 1rem via `.honors .honor-card` because the unlayered button padding reset beats Tailwind utilities.
- A daily cron at 06:00 Hong Kong time and the unauthenticated manual endpoint `GET` or `POST /api/sync/notice-calendar` sync those Nocoly worksheets into D1. Manual sync allows 200 successful calls per Hong Kong day. An incomplete or empty Nocoly snapshot, including an empty 幼鋒會榮譽證 worksheet, is rejected and the existing D1 rows stay. D1 allows at most 100 bound SQL variables per statement, so each sync insert is chunked under that limit.
- Pushing to `main` runs `.github/workflows/void-deploy.yml` (`void deploy`), which provisions D1 and applies migrations. The workflow does not use a `DATABASE_URL` secret. Nocoly keys, `CLERK_SECRET_KEY`, `CANVA_CLIENT_ID`, `CANVA_CLIENT_SECRET`, `TURNSTILE_SECRET`, `TURNSTILE_HOSTNAMES`, and `YOUTUBE_API_KEY` are Worker secrets (`void secret put`). Production `TURNSTILE_HOSTNAMES` is `tuenmunpathfinder.com,www.tuenmunpathfinder.com`. `CANVA_CLIENT_ID` is a server variable, so it must not be a plaintext `void.config.ts` var. `VITE_CLERK_PUBLISHABLE_KEY` is a GitHub Actions variable because production builds ignore `.env`. Local `.env` keeps the Clerk development keys.
